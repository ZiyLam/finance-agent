# Finance Agent｜项目亮点（简历版）

本文是 [项目主说明](../README.md) 的简历与面试提炼版本，仅保留适合对外表达的项目亮点；项目定位、架构职责、运行路径和限制以主说明为准。

## 项目简介

面向个人金融研究的自然语言 Agent。用户可以直接输入公司名称、证券代码或开放问题；系统完成意图识别、证券实体解析、RAG 检索增强与只读数据源调用，输出带数据时效、风险提示和研究边界的分析结果。对于唯一可识别的证券，系统优先走确定性行情快路径；对于港股/ADR 等歧义标的，则并列展示候选结果，避免模型或用户盲目猜测。

## 核心能力与技术栈

- **Agent 框架**：基于 **LangChain 1.x + LangGraph** 的 `create_agent` 构建结构化 Tool-calling 循环（模型决策 → 工具执行 → 工具结果回传 → 再决策），限制工具轮数以控制性能与风险。
- **Tool 治理**：以 LangChain `BaseTool` 适配既有 `ToolRegistry`；工具仍统一经过参数校验、错误隔离和只读约束，可接入 Python 函数、外部 API 与本地数据服务。
- **RAG 方案**：采用 **LCEL + 本地可审阅语料**，检索研究边界、场景路由和数据源能力。当前语料规模较小且需离线可复现，因此使用确定性词法检索，而非过早引入向量数据库；检索器已隔离，后续可平滑替换为 Embedding/向量检索。
- **应用层**：FastAPI 提供 Web API，原生响应式网页提供单一自然语言输入入口；支持 Codex CLI 与千帆等模型适配，支持接入多类只读行情源。
- **可靠性**：加密令牌存储、默认环回访问、数据源回退、外层超时、同标的请求去重、Loading 防重复提交，以及性能回归测试。

## 关键难点与解决方案

| 难点 | 解决方案 |
|---|---|
| 自建 Agent 循环难以继续扩展 | 迁移到 LangChain 负责编排，但保留 `ToolRegistry` 作为数据源唯一执行边界，避免模型绕过只读、校验和错误处理。 |
| 用户输入模糊，金融实体容易歧义 | 使用“实体解析 + 确定性快路径 + 候选并列”的分层策略：高确定性问题不调用模型，歧义问题不强制用户选择也不猜测。 |
| RAG 容易引入不可信内容或过度设计 | 只检索应用内维护的能力说明和研究边界，不放入令牌、原始行情或外部网页内容；以轻量、可复现方案匹配当前规模。 |
| 单证券查询等待长、重复点击堆积 | 将唯一证券改为无需 LLM 的快路径；增加数据源超时、回退、同标的去重和前端遮罩。性能测试覆盖本地快路径 0.5 秒预算与阻塞源超时返回。 |

## 项目结果

- 完成从自建循环到 LangChain Agent 的迁移，并保留领域数据工具的安全边界。
- 建立“自然输入 → RAG 增强 → 确定性快路径或 Agent → 只读行情工具”的完整 Web 链路。
- 建立 134 项自动化测试，覆盖 Agent 工具循环、数据源回退、Web 会话生命周期、访问控制、实体歧义、知识库边界与性能预算。

## 简历表述

> 设计并实现基于 LangChain 1.x 的金融研究 Agent，融合 LCEL 本地 RAG、实体解析和受控 Tool 调用；通过确定性快路径、会话生命周期控制、数据源回退、腾讯 ima 只读知识库边界与性能回归测试提升可靠性，建立 134 项自动化测试保障关键链路。
